## Confirmed correctness problems

### Coordinate and display model

- `GetSystemMetrics(SM_CXSCREEN/SM_CYSCREEN)` captures only the primary display.
- `WindowState="Maximized"` does not create a reliable virtual-desktop overlay.
- WPF layout coordinates are device-independent units while screenshots and Win32 positions can be physical pixels.
- An explicit Per-Monitor DPI V2 manifest and primary-screen/window conversion boundary now exist. Real mixed-DPI validation and monitor-specific overlays/capture metadata remain incomplete.
- Negative coordinates used by monitors left/above the primary monitor are unhandled.
- Model highlights do not identify which captured display or crop they reference.

### Interaction model

- Text entry now uses a dedicated interactive question window; no code path disables overlay click-through. The typing window stays fixed while typing and clamps to the primary work area. Real desktop focus/click-through behavior and mixed-DPI/multi-monitor placement still require manual verification.
- Response bubbles can leave screen bounds near the bottom/right edges.
- The overlay can be included in the screenshot, contaminating model input.
- A ten-second dismissal timer is not tied to reading length, TTS state, or user preference.

### Conversation and transport

- Stable sessions, per-turn request IDs, stale-event rejection, and client state-machine enforcement are implemented.
- Conversation memory is bounded to 100 active sessions and ten user/assistant turns per session, but has no explicit clear event or durable user controls.
- Model output and protocol events now stream; highlighting still relies on parsing a final markdown block.
- Initial and on-demand connection use bounded retry/backoff; proactive background reconnect and richer connection UI remain open.
- Backend failures now use structured error events.

### Voice

- Recorded WAV audio is validated and can be transcribed locally by the optional faster-whisper adapter; the final transcript, detected language, and language confidence are emitted before inference.
- There is no client-side silence detection, partial transcript, device selection, or playback; the runtime/model installation experience and real-audio benchmark remain open.
- Audio is base64 embedded in JSON, adding memory and size overhead.

### Grounding

- A general vision model is prompted to output exact pixels without UI metadata or confidence.
- Highlights are parsed from a markdown fence rather than a validated typed response.
- Primary-screen highlight pixels now convert through WPF's screen-to-window transform; invalid/outside boxes are rejected or clipped to the overlay. Rendering is capped at 32 highlights with bounded labels and requires a screen-sharing turn. This is defensive rendering, not semantic grounding or confidence validation. Typed capture metadata, multi-monitor transforms, and actual DPI testing remain open.

### Lifecycle and maintainability

- The single-instance mutex is retained for the application lifetime.
- Dependencies are installed explicitly from pinned manifests; production packaging remains open.
- Local user preferences have a versioned schema, safe defaults, atomic saves and backups; runtime/provider configuration remains environment-only. Future-schema settings cannot be overwritten by an older client.
- Generated build artifacts, an SDK, and a large installer are stored inside the project folder.
- Source control is initialized on `main`; CI and clean-clone verification remain open.

## Claims that must not be made yet

- “Deep Windows integration” until UIA, DPI, multi-monitor, lifecycle, and installer work are complete.
- “Realtime” until streaming STT/LLM/TTS and interruption meet latency goals.
- “Multi-model routing” until routing is implemented and benchmarked.
- “Computer use” until typed actions, policies, and verification exist.
- “Zero setup” until an ordinary user can install without Python/Ollama knowledge.
- “Enterprise-grade” until security, administration, support, and reliability controls exist.
- “Zero restrictions” for third-party models; licenses must be reviewed per artifact/version.
