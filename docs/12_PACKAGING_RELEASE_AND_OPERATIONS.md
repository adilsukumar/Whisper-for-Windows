# Packaging, Release, and Operations

## End-user installation goal

A nontechnical Windows user downloads one signed installer, sees an honest security prompt, completes guided setup, and asks a first question without installing Python, .NET SDK, Ollama, or manually pulling models.

## Packaging workstreams

### Current engineering package implementation

`dev.ps1 package-client` runs the full code checks, then publishes an unsigned self-contained `win-x64` Release client into a unique `artifacts/developer-client/<timestamp>-<id>` directory. It never deletes/replaces old artifacts. It requires 2 GB free space, emits a per-file SHA-256 manifest, ZIP, and ZIP checksum, and includes explicit developer instructions rather than copying repository files/secrets.

The publication script requires PowerShell 7. An explicit engineering fallback is `tools/Publish-DeveloperClient.ps1 -FrameworkDependent`, which still runs checks but excludes the .NET runtime. Its manifest records `self_contained_dotnet: false`; the receiving machine must already have the .NET 8 Windows Desktop Runtime. This fallback is not zero-setup or an installer.

New publication runtime packages go to `artifacts/nuget-packages` on the repository drive. Existing NuGet packages can be read as a fallback. An optional `artifacts/nuget-feed` local package feed supports official runtime artifacts downloaded separately when NuGet networking fails. No checksum generated by this script is an authenticity signature.

The publication script is implemented but the first self-contained build is not yet verified: official runtime-package downloads have repeatedly timed out on this development connection. Normal build and regression tests pass. Do not treat an empty/incomplete staging folder as a package.

The runtime-dependent fallback successfully published on 2026-09-28 after all checks passed: `artifacts/developer-client/20260928-231926-96a11436.zip`. This verifies publication, not a clean-machine installation or real desktop/microphone operation. Its manifest explicitly declares no bundled .NET runtime, brain, models, or commercial release status. Keep failed self-contained staging outputs separate; they are not release candidates.

Latest verified publication on 2026-09-29: `artifacts/developer-client/20260929-104314-47a05891.zip`, after the Unicode/transport fixes and full check. It supersedes the older developer client for testing; the same runtime/brain/Ollama and non-release limitations apply.

It is not a signed installer, zero-setup build, public beta, or production artifact. Real installer/updater work remains a separate gate. Review dependency redistribution notices before sharing externally.

### Application

- Publish self-contained .NET builds for supported architectures.
- Package orchestrator/runtime dependencies or migrate them behind a managed sidecar.
- Keep model files outside the application binary and download on demand.
- Separate app updates from large model updates.

### Installer

- Choose MSIX, WiX/Burn, or another mature signed bootstrapper after prototyping install/update constraints.
- Install per-user by default without elevation where feasible.
- Show disk/download requirements before fetching models.
- Register startup only with explicit opt-in.
- Support repair, clean uninstall, and a clear keep/delete-data choice.

### Code signing

- Obtain a reputable code-signing certificate.
- Sign executable, sidecars, installer, updater, and relevant scripts.
- Timestamp signatures.
- Verify signatures/hashes before executing updates or downloaded runtimes.

## Dependency and model manager

- Manifest contains artifact ID, version, URL, size, SHA-256, license, hardware requirements, and compatible app versions.
- Downloads resume and verify before activation.
- Keep last-known-good artifact for rollback.
- Remove unused models through settings.
- Never redistribute an artifact until its license and notice requirements are recorded.

## Update channels

- Development/nightly: internal and unstable.
- Private beta: invited users; verbose diagnostics.
- Public beta: opt-in prerelease.
- Stable: staged rollout with automatic pause on regressions.

Update process:

1. CI builds reproducibly and tests artifacts.
2. Generate SBOM, notices, checksums, and signed metadata.
3. Publish to selected channel.
4. Roll out 5% → 25% → 100% based on health.
5. Support one-click rollback to last-known-good version.

## Diagnostics

The diagnostics panel checks:

- App/orchestrator versions and protocol compatibility.
- Microphone/output devices and permissions.
- Capture and UIA availability.
- Model/provider health and model presence.
- GPU/runtime detection and disk space.
- Local endpoint authentication.
- Update channel/status.

“Copy diagnostics” must produce a redacted bundle with explicit preview.

## Crash and failure recovery

- Client monitors sidecar health and restarts with bounded backoff.
- Sidecar failure never leaves an invisible stuck input hook.
- Save state atomically and recover from partial writes.
- Detect repeated crash loops and start in safe mode with actions/plugins disabled.
- Offer last session diagnostics without uploading automatically.

## Support operations

- In-app report flow with consented diagnostics attachment.
- Public status page only when cloud dependencies become material.
- Triage runbook by error code and release version.
- Document supported OS/hardware/provider matrix.
- Publish known issues and workarounds.
- Security contact and vulnerability disclosure policy before 1.0.

## Release checklist

- Version and changelog updated.
- All gates in `15_DEFINITION_OF_DONE.md` pass.
- Clean VM install, update from prior stable, rollback, and uninstall pass.
- Licenses/notices/SBOM current.
- Signatures and hashes verified.
- Privacy/security changes reviewed.
- Support docs and known issues published.
- Rollout and rollback owners assigned.
